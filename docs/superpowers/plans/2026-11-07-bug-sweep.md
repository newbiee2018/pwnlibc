# pwnlibc Bug Sweep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the 2026-11-07 bug sweep: sudo ownership repair, suite-map refresh + unknown-suite warning, full-lib-dir verify, opt-in GPG signature checking, builder source-reuse + configurable timeout, `download-all --source`, `download latest`, `--version`, retrying source HEAD checks — closed by a structured bug-hunt review pass for anything the sweep missed.

**Architecture:** No new state and no workflow changes — every fix rides the existing modules. Two new small modules for genuinely new concerns (`pwnlibc/ownership.py`, `pwnlibc/signatures.py`); everything else is targeted edits in `cli.py`/`downloader.py`/`builder.py` plus tests using the suite's existing mock idioms.

**Tech Stack:** Python 3.8+ (click >=8, rich >=13 only), gpgv as an *optional* external tool, pytest with network/slow markers deselected by default.

**Spec:** `docs/superpowers/specs/2026-11-07-bug-sweep-design.md` — the settled brainstorm scope; read it first.

## Global Constraints

- Python 3.8 floor: every new module starts with `from __future__ import annotations`; use `os.readlink` (not `Path.readlink`), no 3.9+-only APIs.
- Runtime deps stay `click>=8.0, rich>=13.0` — no python-gnupg; gpgv runs via `subprocess` and degrades to a warning when absent.
- New tests run under the default offline profile (`pytest` deselects `network`/`slow`); use the suite's existing idioms: `_serve_indices`, `_FakeResponse`, `_packages_index`, `_verify_pkg` (tests/test_downloader.py), `@patch("pwnlibc.builder.subprocess.run")` (tests/test_builder.py), `tmp_glibc_dir`/`populated_glibc_dir` (tests/conftest.py).
- Do not touch the load-bearing invariants: `.debug/` flat layout, patchelf order (rpath → replace-needed → interpreter), cross-family revision isolation, filesystem-as-source-of-truth.
- Console output style: `console.print` with the existing red/yellow/green/dim markup; warnings that aren't failures go to stderr.
- Mirrors are only fetched over https (reuse `_index_urls`' base-forcing behavior).

## Review Focus

Five conditions the spec implies but no happy path exercises — each pinned to its owning task:

1. Root-owned leftovers from **pre-fix sudo runs** → `remove` prints the chown hint and exits 1, never a traceback → Task 1 test.
2. A **brand-new release (2.42+) missing from the suite map** → download warns once on stderr, still succeeds, nothing negative-cached → Task 2 test.
3. A **cached Packages index that disagrees with the signed Release** (tamper or stale cache) → `--verify-signatures` reports FAIL and the command exits 1 → Task 4 test.
4. **Nested lib subdirs (`gconv/`) and old-naming (≤2.33) symlink chains** → full-dir verify recurses, compares symlink targets, produces no false MISMATCH → Task 3 tests.
5. A **local source dir that exists but is incomplete** (no `configure`) → build falls back to downloading instead of failing configure → Task 5 test.
6. **`latest` for an arch whose chain is legacy-limited (powerpc) or empty** → resolves to the newest that actually exists there, or errors per-arch without aborting the other arches → Task 7 tests.
